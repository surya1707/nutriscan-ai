# NutriScan AI — Mobile

The Flutter mobile app for NutriScan AI. Scans ingredient labels via camera OCR or barcode, computes a personalised safety score, and syncs scan history and user profiles with the FastAPI backend.

---

## Tech Stack

| Layer | Technology |
|---|---|
| Framework | [Flutter](https://flutter.dev/) (Dart SDK ≥ 3.0) |
| State Management | [Riverpod](https://riverpod.dev/) (`flutter_riverpod ^2.4.9`) |
| Navigation | [go_router](https://pub.dev/packages/go_router) |
| Local Database | [Drift](https://drift.simonbinder.eu/) (SQLite, async) |
| HTTP Client | [Dio](https://pub.dev/packages/dio) with auth interceptor |
| Auth | Firebase Auth + Google Sign-In |
| Camera / OCR | `camera`, `google_mlkit_text_recognition`, `mobile_scanner` |
| Barcode | `google_mlkit_barcode_scanning` |
| Testing | `flutter_test`, `mocktail`, `network_image_mock` |

## Firebase Setup

The app requires two files that are gitignored and must be generated per-developer:

### 1. `android/app/google-services.json`

1. Open the [Firebase Console](https://console.firebase.google.com/) for the NutriScan project.
2. Go to **Project Settings → Your apps → Android app**.
3. Download `google-services.json`.
4. Place it at `mobile/android/app/google-services.json`.

### 2. `lib/firebase_options.dart`

This file is generated by the [FlutterFire CLI](https://firebase.flutter.dev/docs/cli/). Install it once, then run:

```bash
dart pub global activate flutterfire_cli
flutterfire configure --project=<your-firebase-project-id>
```

This creates `lib/firebase_options.dart`. Use `lib/firebase_options.dart.example` as a reference for the expected structure.

## Running the App

The app uses `--dart-define-from-file` to load the backend URL. Config files live in `mobile/config/`.

### Development

Targets `http://localhost:8000` by default. Make sure the backend is running locally (or via Docker Compose).

```bash
flutter run --dart-define-from-file=config/dev.json
```

For a physical Android device on the same network, update `config/dev.json` with your machine's local IP (e.g., `http://192.168.x.x:8000`) — `localhost` is not reachable from a real device.

### Staging

Update `config/staging.json` with your staging backend URL, then:

```bash
flutter run --dart-define-from-file=config/staging.json
```

### Production

Update `config/prod.json` with the production URL, then:

```bash
# Run in release mode (requires keystore — see Android Release Signing)
flutter run --release --dart-define-from-file=config/prod.json

# Build APK
flutter build apk --dart-define-from-file=config/prod.json

# Build App Bundle (recommended for Play Store)
flutter build appbundle --dart-define-from-file=config/prod.json
```

## Android Release Signing

A release build requires a keystore. The repository includes only a template:

```
mobile/android/keystore.properties.example
```

### Steps

1. **Generate your keystore** (one-time):
   ```bash
   keytool -genkey -v -keystore upload-keystore.jks -storetype JKS \
     -keyalg RSA -keysize 2048 -validity 10000 -alias upload
   ```
   Store the `.jks` file outside the repository.

2. **Create `keystore.properties`** in `mobile/android/` (gitignored):
   ```properties
   storePassword=your_store_password
   keyPassword=your_key_password
   keyAlias=upload
   storeFile=/absolute/path/to/upload-keystore.jks
   ```

3. The `build.gradle.kts` is already wired to read this file — no further changes needed.

> Without `keystore.properties`, release builds will fail. Debug builds are unaffected.

## Architecture

### Offline-First Sync

All data is written to local Drift (SQLite) tables immediately with `isSynced = false`. A background sync then pushes the data to the FastAPI backend via `ApiService` and flips `isSynced = true` on success. On app load, cloud data is pulled down and merged with local state.

```
User Action
    │
    ▼
Drift (local) ──[immediate write, isSynced=false]──► UI updates instantly
    │
    ▼
ApiService (Dio) ──[background push]──► FastAPI backend
    │
    ▼
On success: update local row isSynced=true
```

### Auth Token Flow

`api_service.dart` attaches a Dio `InterceptorsWrapper` that:
1. Reads `FirebaseAuth.instance.currentUser?.getIdToken()` before every request.
2. Attaches it as `Authorization: Bearer <token>`.
3. On a **401 response**, forces a token refresh via `getIdToken(true)` and retries the request once.
4. If the retry also fails, surfaces a clear `DioException` for the UI to catch.

### State Management

| Provider | Type | Purpose |
|---|---|---|
| `authProvider` | `AsyncNotifierProvider` | Firebase auth state, Google Sign-In, guest mode |
| `userProfileProvider` | `StateNotifierProvider` | Profile load, save, cloud sync |
| `scanHistoryProvider` | `StreamProvider` | Live stream of Drift scan history |
| `recentScansProvider` | `FutureProvider` | Latest 5 scans for home screen |
| `scanStatsProvider` | `FutureProvider` | Aggregate stats (total scans, avg score) |
| `scanProvider` | `StateNotifierProvider` | Scanner state machine (idle/scanning/processing/result) |
